# Authz-coverage scanner baseline — req-tap-auth-policy-9.
#
# Each non-comment line is a STABLE key `<relative-path>::<enclosing-qualname>::<sink>`
# identifying a call to a privileged graph sink (write_batch / grift_import / the
# Search+Gryphon executors / the _*_internal write helpers) whose enclosing function
# is NOT gated by @requires_capability or an authorized() block — the build-time dual
# of the stateless enforcement backstop (tap/authz_coverage.py). It catches the
# forgotten-gate-by-a-privileged-actor case the runtime backstop cannot.
#
# The key is line-number-independent BY DESIGN: unrelated edits that move a sink up
# or down its file do NOT churn this baseline. Only gating/deleting the sink, or
# renaming its enclosing function, changes a key. (Prior format was <path>:<lineno>,
# which drifted on every unrelated edit above a grandfathered sink.)
#
# These are grandfathered so the gate is green on day one; the set ratchets to
# ZERO as the rest of the authZ build-out lands — this file is that worklist.
# test_authz_coverage.py fails on any NEW entry and any STALE entry, so a fix must
# delete its line here. Do not add rows except as a deliberate, reviewed last
# resort: prefer a @requires_capability/authorized() gate, or a
# `# TAP-AUTHZ-COV: <reason>` comment when the call is provably gated by a caller
# the per-function scanner cannot see (a plain comment, NOT a noqa code — ruff
# rejects the hyphenated token).
#
